# Как подключиться к проекту и начать работать с Claude Code

Инструкция из двух частей.

- **Часть 1 — для Тани.** Один скрипт настраивает всё: Git, вход в GitHub,
  скачивание сайта. Потом — как работать день за днём.
- **Часть 2 — для Дмитрия.** Как дать Тане доступ к репозиторию и защитить
  живой сайт от случайных поломок.

Репозиторий проекта: <https://github.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing>
Живой сайт (публикуется автоматически из ветки `main`):
<https://dmitry-rukhlenko.github.io/tatsiana-fitness-coach-landing/>

---

## Часть 1. Для Тани

### Что такое все эти слова

- **Git** — программа, которая хранит историю изменений файлов. Любую правку
  можно откатить, а два человека могут работать над одним сайтом, не затирая
  друг друга.
- **GitHub** — сайт, где лежит общая копия проекта («репозиторий»). Оттуда же
  сайт публикуется в интернет: всё, что попадает в главную ветку `main`,
  через минуту видят посетители.
- **Claude Code** — приложение Claude, в котором ты пишешь задачи обычным
  языком («поменяй текст в блоке о консультации»), а Claude сам правит файлы,
  запускает команды и показывает результат. Команды знать не нужно.
- **Ветка (branch)** — отдельная «копия» проекта для одной задачи. Ты
  работаешь в своей ветке, а когда всё готово, Дмитрий переносит изменения в
  `main`. Так живой сайт не ломается на полпути.

### Шаг 1. Аккаунт на GitHub (5 минут)

1. Открой <https://github.com/signup> и зарегистрируйся.
2. Подтверди почту по письму от GitHub.
3. Сообщи Дмитрию свой **логин** (имя пользователя, не почту).
4. Когда придёт письмо «invited you to collaborate», нажми в нём
   **Accept invitation**. Если письмо потерялось, прими приглашение здесь:
   <https://github.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing/invitations>

Без приглашения сайт можно скачать и смотреть, но нельзя отправлять правки
обратно. Скрипт на шаге 3 это проверит и подскажет.

### Шаг 2. Приложение Claude

1. Скачай Claude для компьютера: <https://claude.ai/download>, установи, войди.
2. Для Claude Code нужна подписка Pro или выше. Если её нет — обсуди с Дмитрием.

### Шаг 3. Запустить скрипт настройки (Mac)

Скрипт сам поставит недостающие программы, войдёт в GitHub, скачает проект и
проверит доступ. Если что-то уже сделано, он этот шаг пропустит, поэтому
запускать его можно сколько угодно раз.

1. Открой **Терминал**: нажми `Cmd + пробел`, напиши `Терминал` (или
   `Terminal`), Enter.
2. Скопируй целиком строку ниже, вставь в Терминал и нажми Enter:

```bash
curl -fsSL https://raw.githubusercontent.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing/main/setup-tanya.sh -o ~/Downloads/setup-tanya.sh && bash ~/Downloads/setup-tanya.sh
```

3. Дальше просто читай, что пишет скрипт. Он может попросить:
   - **пароль от Mac** — для установки программ (символы при вводе не
     видны, это нормально, просто набери и нажми Enter);
   - **нажать «Установить»** в окне macOS, если нет Git;
   - **ввести код в браузере** — появится код вида `XXXX-XXXX`, откроется
     страница GitHub, введи код и нажми **Authorize**;
   - **ответить y или n**, ставить ли Node.js для автопроверок. Можно
     ответить `n` — для правок текста он не нужен.
4. В конце скрипт напишет «🟢 Готово» и откроет Claude. Проект лежит в папке
   `Coding/tatsiana-fitness-coach-landing` в твоей домашней папке.

Если скрипт остановился с красным 🔴, прочитай сообщение: там написано, что
исправить. После этого запусти ту же строку ещё раз.

Если у тебя **Windows**, скрипт не подойдёт: напиши Дмитрию, для Windows есть
другой путь (см. Часть 2, пункт 2.4).

### Шаг 4. Открыть проект в Claude Code

1. В приложении Claude открой вкладку **Code**.
2. Создай новую сессию и выбери папку `Coding/tatsiana-fitness-coach-landing`.
3. С этого момента Claude видит все файлы сайта. Для знакомства напиши:

```text
Прочитай ONBOARDING.md, PRODUCT.md, DESIGN.md и ROADMAP.md и коротко расскажи,
что это за сайт, какие правила по дизайну и тексту, как тут принято работать
и что ещё не сделано.
```

Главные файлы проекта:

| Файл / папка | Что это |
| --- | --- |
| `index.html` | Главная страница, тексты на немецком и английском |
| `style.css` | Внешний вид: цвета, шрифты, отступы |
| `script.js` | Поведение: переключение языка, форма |
| `impressum.html` | Impressum и Datenschutz (обязательно для Германии) |
| `images/` | Фотографии, которые публикуются на сайте |
| `demo/` | Демо-варианты редизайна (A, B, C), на сайт пока не перенесены |
| `PRODUCT.md`, `DESIGN.md` | Описание бренда и правила дизайна |
| `ROADMAP.md` | Что нужно сделать до настоящего запуска |

Папки `original images/` в скачанной копии **не будет**: исходные фото
намеренно не публикуются в GitHub. Если нужны, Дмитрий передаст их отдельно.

### Шаг 5. Посмотреть сайт у себя

Попроси Claude:

```text
Запусти локальный сервер и открой сайт в браузере, чтобы я посмотрела.
```

Он поднимет сервер и покажет страницу по адресу `http://localhost:8765`.
Это твоя локальная копия: что бы ты ни меняла, в интернете ничего не
поменяется, пока изменения не попадут в `main`.

### Шаг 6. Как вносить правки (главное правило)

**Никогда не работай прямо в ветке `main`.** Всё, что попадает в `main`,
сразу публикуется на живой сайт. Порядок такой:

1. **Обновиться и создать ветку** для задачи:

   ```text
   Переключись на main, подтяни последние изменения (git pull) и создай
   новую ветку для задачи: <коротко, о чём задача>.
   ```

   Claude сам придумает имя ветки, например `tanya/update-consultation-text`.

2. **Сделать правки** обычным языком:

   ```text
   В блоке о консультации на главной замени немецкий текст на: «...».
   Английскую версию переведи сама и покажи мне перевод до правки.
   ```

   Claude покажет, что поменял. Открой локальный сайт и проверь глазами.

3. **Проверить, что ничего не сломалось** (если ставила Node.js):

   ```text
   Запусти npm test и скажи, прошли ли проверки.
   ```

4. **Сохранить и отправить:**

   ```text
   Закоммить изменения с понятным сообщением, отправь ветку на GitHub
   и создай pull request на main. В описании напиши, что изменилось
   и что нужно проверить.
   ```

   **Pull request** (PR) — запрос «перенесите мои изменения в main».
   Дмитрий получит уведомление, посмотрит, при необходимости попросит
   поправить и нажмёт Merge. После этого сайт обновится сам.

5. **Следующая задача — новая ветка.** Начинай снова с пункта 1.

### Полезные фразы для Claude

- «Покажи, что изменилось с последнего коммита».
- «Отмени последние изменения в файле style.css».
- «Что нового в ветке main на GitHub? Есть ли что-то от Дмитрия?»
- «Объясни, что делает этот кусок кода, простыми словами».
- «Сделай скриншот сайта на телефоне и на компьютере».

### Если что-то пошло не так

- **«Permission denied» или «403» при отправке на GitHub.** Приглашение не
  принято (Шаг 1, пункт 4) или не выполнен вход. Запусти скрипт из Шага 3
  ещё раз — он покажет, чего не хватает.
- **Claude говорит, что команда `gh` или `git` не найдена.** Перезапусти
  приложение Claude. Если не помогло — снова запусти скрипт.
- **Конфликт (merge conflict).** Дмитрий поменял тот же файл. Скажи Claude:
  «есть конфликт, помоги его разрешить, покажи оба варианта».
- **Что-то сломалось и непонятно что.** Пока изменения не в `main`, живой
  сайт в порядке. Напиши Дмитрию и не трогай ветку `main`.

## Часть 2. Для Дмитрия

### 2.1. Выдать Тане доступ

Репозиторий личный и публичный. Клонировать его может кто угодно, а право
пушить дают только соавторам (collaborators). У личных репозиториев одна
роль для соавтора — запись (write); тонких ролей, как в организациях, нет.

**Через сайт:**

1. <https://github.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing/settings/access>
2. **Add people** → ввести логин Тани → **Add to repository**.
3. Таня получит письмо и должна нажать Accept. Пока не приняла, она висит
   в списке как «Pending invite».

**Через терминал** (подставь её логин):

```bash
gh api -X PUT repos/dmitry-rukhlenko/tatsiana-fitness-coach-landing/collaborators/ЛОГИН_ТАНИ
```

Проверить, принято ли:

```bash
gh api repos/dmitry-rukhlenko/tatsiana-fitness-coach-landing/collaborators --jq '.[].login'
```

### 2.2. Защитить `main` (рекомендую сделать сразу)

GitHub Pages публикует сайт из ветки `main`, папка `/`. Сейчас `main` не
защищена: соавтор может запушить туда напрямую, и правка мгновенно уйдёт на
живой сайт. Инструкция говорит Тане работать через ветки и pull request, но
лучше, чтобы это обеспечивал GitHub, а не память.

1. <https://github.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing/settings/rules>
2. **New ruleset** → **New branch ruleset**.
3. Name: `protect-main`. Enforcement status: **Active**.
4. Target branches → **Add target** → **Include default branch**.
5. Включить:
   - **Restrict deletions**
   - **Block force pushes**
   - **Require a pull request before merging** (Required approvals можно
     оставить 0; важно само требование PR. Поставишь 1 — мержить сможешь
     только ты после одобрения)
6. В Bypass list добавить **Repository admin**, чтобы ты мог коммитить в
   `main` напрямую, когда работаешь один.
7. **Create**.

Rulesets на бесплатном плане работают для публичных репозиториев — этот
публичный, ограничений нет.

### 2.3. Скрипт `setup-tanya.sh`

Лежит в корне репозитория. Таня скачивает его по raw-ссылке из ветки `main`,
поэтому **до того как отправлять ей инструкцию, скрипт должен быть
запушен в `main`**. Что он делает (каждый шаг пропускается, если уже
сделан):

1. Git через Xcode Command Line Tools.
2. GitHub CLI: через Homebrew, если он есть, иначе официальный `.pkg`
   с <https://github.com/cli/cli/releases>.
3. `gh auth login` через браузер и `gh auth setup-git`.
4. `user.name` и `user.email` для git. Почта — noreply-адрес GitHub,
   реальный ящик в историю не попадает.
5. Клон в `~/Coding/tatsiana-fitness-coach-landing` (или `git fetch`, если уже есть).
6. Проверка права на запись через API; если нет — открывает страницу
   приглашений.
7. Опционально Node.js, `npm install`, `npx playwright install chromium`.
8. Открывает приложение Claude или страницу загрузки.

Переменные для отладки: `SETUP_DIR` (другая папка), `SETUP_NO_OPEN=1`
(ничего не открывать), `SETUP_NODE=yes|no` (без вопроса про Node).
Проверен прогоном на macOS 20 ноября 2026: все шаги прошли.

### 2.4. Если у Тани Windows

Скрипт только для macOS. Для Windows ручной путь короткий: в PowerShell

```powershell
winget install --id Git.Git -e; winget install --id GitHub.cli -e
```

затем перезапустить PowerShell и выполнить `gh auth login`,
`gh auth setup-git`, `gh repo clone dmitry-rukhlenko/tatsiana-fitness-coach-landing`.
Полный аналог скрипта под Windows можно сделать отдельной задачей.

### 2.5. Что ещё учесть

- `original images/` в `.gitignore`. Если Тане нужны исходники фото,
  передай их отдельно, не через Git.
- Уведомления о PR придут на почту GitHub. Мержить можно на сайте или так:

```bash
gh pr list --repo dmitry-rukhlenko/tatsiana-fitness-coach-landing
```

```bash
gh pr merge НОМЕР --repo dmitry-rukhlenko/tatsiana-fitness-coach-landing --squash --delete-branch
```

- Коллаборатор публичного личного репозитория может менять Issues,
  создавать ветки и релизы, но не может менять настройки репозитория,
  удалять его или управлять доступом. Это как раз нужный уровень.
