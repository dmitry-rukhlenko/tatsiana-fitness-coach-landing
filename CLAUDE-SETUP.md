# Инструкция для Claude: подключить Таню к проекту

> **Таня, этот файл не нужно читать самой.** Сначала сделай Шаги 1–3 из
> инструкции (аккаунт GitHub, приложение Claude, Git). Потом открой в Claude

> «Загрузки»), перетащи этот файл в окно чата и напиши:
> **«Проведи меня по этой инструкции»**. Дальше Claude всё объяснит.

## Для Claude: кто пользователь и что нужно сделать

Ты помогаешь Тане (Tatsiana Rukhlenko). Она фитнес-тренер, а не программист:
никогда не работала с командной строкой, Git и GitHub. У неё **Windows**.
Цель сессии — чтобы у неё была скачанная копия сайта, вход в GitHub и
понимание, как безопасно вносить правки.

**Главное ограничение: Таня не пользуется командной строкой.** Не проси её
открывать PowerShell, cmd или Git Bash и вставлять туда команды. Всё, что
делает она, — это установщики, кнопки и браузер. Команды запускаешь только
ты сам, своими инструментами, и только для проверки.

Факты о проекте:

- Репозиторий: <https://github.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing>
  (публичный, владелец — Дмитрий, логин `dmitry-rukhlenko`).
- Живой сайт публикуется GitHub Pages прямо из ветки `main`:
  <https://dmitry-rukhlenko.github.io/tatsiana-fitness-coach-landing/>
- Ветка `main` защищена: прямой пуш запрещён, только pull request.
  Дмитрий проверяет и мержит.
- Сайт клонируется через **GitHub Desktop** в папку по умолчанию:
  `C:\Users\<имя>\Documents\GitHub\tatsiana-fitness-coach-landing`
  (в твоей оболочке это `$HOME/Documents/GitHub/tatsiana-fitness-coach-landing`).
  Папка «Документы» может быть перенесена в OneDrive — тогда ищи там.
- Вход для `git push` даёт **Git Credential Manager**, который входит в
  Git for Windows: при первом пуше он сам покажет окно входа через браузер.
- Программы `gh` (GitHub CLI) у неё нет, и ставить её не нужно. Pull request
  создаётся по ссылке на сайте GitHub.

## Как с ней разговаривать

- Только по-русски, простыми словами, короткими сообщениями.
- Каждое новое слово (Git, GitHub, ветка, коммит, pull request) объясняй
  один раз, в одном предложении, бытовой аналогией.
- Один шаг за раз. Скажи, что нажать, дождись её ответа, проверь результат
  сам и только потом переходи дальше.
- Называй кнопки так, как они подписаны на экране (по-английски, если
  интерфейс английский), и говори, где они находятся.
- Не показывай вывод команд. Перескажи итог одной фразой: «✅ Git есть»,
  «⏳ приглашение ещё не принято».
- Если что-то не получается дважды — не импровизируй. Предложи написать
  Дмитрию и приложить скриншот экрана.

## Чего не делать

- Не проси её вводить пароли или коды в чат. Вход в GitHub проходит только
  в браузере и в окнах программ.
- Не проси её пользоваться командной строкой (см. выше).
- Не ставь программы сам без её явного согласия. Если чего-то не хватает,
  дай ей ссылку на установщик.
- Не меняй глобальные настройки git, если они уже заданы.
- Не пушь в `main`, не меняй настройки репозитория, не принимай за неё
  приглашения и условия на сайтах.
- Не редактируй файлы сайта в этой сессии: сейчас задача — только
  подключение.

## Шаги

### Шаг 0. Знакомство и проверка

Коротко поздоровайся и объясни план: проверить, что всё установлено →
GitHub Desktop: войти и скачать сайт → проверка → открыть сайт в Claude.
Скажи, что это займёт 20–30 минут и что сломать ничего нельзя.

Сам проверь (это работает и в Git Bash, и в PowerShell):

```bash
git --version
```

Если Git есть — скажи «✅ Git установлен». Если нет, дай ссылку
<https://git-scm.com/downloads/win> и объясни: скачать 64-битный
установщик, на всех экранах нажимать **Next**, в конце **Install** и
**Finish**. После установки ей нужно полностью закрыть Claude и открыть
снова, а потом вернуться в эту сессию.

Спроси, есть ли у неё аккаунт GitHub и отправила ли она логин Дмитрию.
Если нет — проведи по регистрации на <https://github.com/signup> и попроси
отправить логин Дмитрию: он пригласит её в проект, придёт письмо «invited you
to collaborate» с кнопкой **Accept invitation**. Ждать письма не обязательно.

### Шаг 1. GitHub Desktop: установка и вход

Проверь, не скачан ли уже сайт:

```bash
git -C "$HOME/Documents/GitHub/tatsiana-fitness-coach-landing" status -sb
```

Если команда показывает `## main...origin/main` — сайт уже есть, переходи к
Шагу 3.

Иначе веди её по шагам:

1. Открыть <https://desktop.github.com/download/>, нажать кнопку скачивания
   для Windows, запустить файл. Программа поставится сама и откроется.
2. Нажать **Sign in to GitHub.com** → в браузере войти в GitHub → нажать
   **Authorize desktop** → на вопрос браузера «Открыть GitHub Desktop?»
   нажать **Открыть**.
3. Экран **Configure Git**: имя оставить. Если среди почт есть адрес на
   `users.noreply.github.com`, выбрать его — так её настоящая почта не
   попадёт в публичную историю. Нажать **Finish**.

### Шаг 2. Скачать сайт

1. В окне «Let's get started» выбрать **Clone a repository from the
   Internet…** (или меню **File → Clone repository…**).
2. Вкладка **URL**, в верхнее поле вставить
   `dmitry-rukhlenko/tatsiana-fitness-coach-landing`.
3. **Local path** не трогать. Нажать **Clone**, подождать минуту.

### Шаг 3. Проверить результат

Сам выполни и перескажи итог одной строкой на каждый пункт:

```bash
git -C "$HOME/Documents/GitHub/tatsiana-fitness-coach-landing" status -sb
```

```bash
git config --global user.name; git config --global user.email
```

Если папки по этому пути нет, найди её: она может быть в OneDrive
(`$HOME/OneDrive/Documents/GitHub/...` или с русским именем папки). Спроси
Таню, какой путь был в поле Local path.

Проверка доступа на запись. Эта команда ничего не отправляет, она только
спрашивает GitHub, можно ли будет отправлять:

```bash
git -C "<путь к проекту>" push --dry-run origin HEAD:refs/heads/access-check
```

- Если появилось окно **Connect to GitHub** — скажи ей нажать **Sign in with
  your browser** и **Authorize** в браузере. Это нужно один раз.
- Ответ без ошибок — ✅ доступ есть.
- `403` или `Permission denied` — ⏳ приглашение не принято или ещё не
  отправлено. Дай ссылку
  <https://github.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing/invitations>,
  пусть нажмёт **Accept**. Если там пусто, пусть напишет Дмитрию свой логин.
  Это не мешает продолжить: смотреть и править сайт у себя уже можно.

| Проверка | Хорошо | Если нет |
| --- | --- | --- |
| Git | версия выводится | Установить Git (Шаг 0) |
| Копия сайта | `## main...origin/main` | Повторить Шаг 2 |
| Подпись | имя и почта заданы | Сказать Тане и Дмитрию, сам не исправляй |
| Доступ на запись | `push --dry-run` без ошибок | Принять приглашение |

### Шаг 4. Открыть проект в Claude Code

Объясни, что эта сессия была только для настройки. Работать над сайтом
нужно в новой сессии, открытой в папке проекта, — тогда Claude видит все
файлы сайта.

1. Новая сессия во вкладке **Code**.
2. Выбрать папку **Документы → GitHub → tatsiana-fitness-coach-landing**
   (или тот путь, который был в Local path).
3. Первое сообщение в новой сессии:

```text
Прочитай ONBOARDING.md, PRODUCT.md и DESIGN.md и расскажи простыми словами,
что это за сайт, какие тут правила для текста и дизайна и как принято работать.
```

### Шаг 5. Объяснить, как будет устроена работа

Перескажи своими словами, коротко:

- Живой сайт — ветка `main`. Её напрямую не меняют, GitHub это и не даст.
- Каждая задача — новая ветка («черновик»): обновить `main`, создать
  ветку, сделать правки, посмотреть сайт у себя, сохранить и отправить.
- После отправки Claude даёт ссылку, она нажимает на сайте GitHub кнопку
  **Create pull request**. Дмитрий проверит и опубликует.
- Для каждого шага достаточно написать Claude обычными словами; готовые
  фразы есть в `ONBOARDING.md`, раздел «Шаг 7. Как делать правки».
- Пока Дмитрий не опубликовал pull request, живой сайт в безопасности, что
  бы ни случилось с её копией.

### Шаг 6. Итог

Дай ей короткий итог с отметками ✅/⏳/❌ по пунктам: аккаунт GitHub, Git,
GitHub Desktop и вход, копия сайта, доступ на запись. Для ⏳ и ❌ напиши,
что сделать и кому написать. Если доступа на запись ещё нет, напомни
отправить Дмитрию логин.

## Заметки для будущих сессий в этом проекте

Когда Таня работает над сайтом в папке проекта:

- `gh` нет. Чтобы создать pull request, после `git push -u origin <ветка>`
  дай ей ссылку
  `https://github.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing/compare/main...<ветка>?expand=1`
  и попроси нажать **Create pull request**. Текст описания предложи
  заранее, чтобы она вставила его в поле.
- Python на Windows обычно не установлен. Чтобы показать сайт, достаточно
  открыть `index.html` в браузере: это статический сайт без сборки.
- Для `npm test` нужен Node.js (<https://nodejs.org/>); без него проверку
  пропусти, Дмитрий проверит при приёме.
