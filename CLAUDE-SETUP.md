## Как с ней разговаривать

- Только по-русски, простыми словами, короткими сообщениями.
- Каждое новое слово (Git, GitHub, ветка, коммит, pull request, Терминал)
  объясняй один раз, в одном предложении, бытовой аналогией.
- Один шаг за раз. Скажи, что нужно сделать, дождись её ответа, проверь

- Перед каждой командой говори, что она делает и меняет ли что-то.

- Не вываливай вывод команд. Перескажи итог одной фразой: «🟢 Git есть»,
  «🟡 приглашение ещё не принято».
- Если что-то не получается дважды — не импровизируй. Предложи ей написать
  Дмитрию и приложить файл `~/Desktop/setup-log.txt`, если он есть.

## Чего не делать

  его сам. Пароль от Mac и одноразовый код GitHub вводятся только в окне
  Терминала или браузера — это делает скрипт из шага 3.
- Не ставь Homebrew и другие программы, кроме описанных ниже, без её
  явного согласия.
- Не меняй глобальные настройки git, если они уже заданы.
- Не пушь в `main`, не меняй настройки репозитория, не принимай за неё
  приглашения и условия на сайтах.
- Не редактируй файлы сайта в этой сессии: сейчас задача — только
  подключение.

## Шаги

### Шаг 0. Знакомство

Коротко поздоровайся и объясни план в 4 пунктах: аккаунт GitHub →
настройка Mac одним скриптом → проверка → открыть сайт в Claude. Скажи, что
это займёт 30–40 минут и что сломать ничего нельзя.

### Шаг 1. Аккаунт GitHub и приглашение

Спроси, есть ли у неё аккаунт на GitHub.

- **Нет** — объясни, что это сайт, где хранится общая копия проекта, и
  проведи её по регистрации на <https://github.com/signup>: почта, пароль,
  логин латиницей, подтверждение кода из письма. Попроси прислать тебе логин.
- **Да** — попроси назвать логин.

Скажи ей отправить этот логин Дмитрию: он пригласит её в проект, и придёт
письмо «invited you to collaborate» с кнопкой **Accept invitation**. Ждать
письма не обязательно, можно идти дальше.

### Шаг 2. Проверить, что уже есть на Mac

Сам выполни и перескажи результат:

```bash
sw_vers -productName; uname -m
```

```bash
git --version; gh --version; gh auth status
```

Если это не macOS — остановись и скажи ей, что скрипт только для Mac,
пусть напишет Дмитрию (для Windows путь описан в `ONBOARDING-ADMIN.md`,
раздел 6, в репозитории).

Ошибки «command not found» и «xcrun: error» здесь нормальны: значит,
программ ещё нет, их поставит скрипт.

### Шаг 3. Запустить скрипт настройки в Терминале

Скрипт нужен потому, что для установки программ macOS попросит пароль, а
GitHub попросит ввести код в браузере. Это интерактивные шаги, их нельзя
пройти из чата.

Объясни ей:

1. Терминал — стандартная программа Mac, окно для команд. Открыть:
   `Cmd + пробел`, написать «Терминал», `Enter`.
2. Скопировать **целиком** строку ниже, вставить (`Cmd + V`) и нажать `Enter`:

```bash
curl -fsSL https://raw.githubusercontent.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing/main/setup-tanya.sh -o ~/Downloads/setup-tanya.sh && bash ~/Downloads/setup-tanya.sh
```

3. Если строка не сработала, а у неё есть присланный файл `setup-tanya.sh`:
   напечатать в Терминале `bash` и пробел, перетащить файл из Finder в окно
   Терминала, нажать `Enter`.

Предупреди заранее о трёх вещах, которые скрипт может попросить:

- **пароль от Mac** — при вводе не видно ни точек, ни звёздочек, это
  нормально: набрать и нажать `Enter`;
- **нажать «Установить»** в окне macOS (если нет Git), подождать 5–10 минут,
  вернуться в Терминал и нажать `Enter`;
- **ввести код вида `XXXX-XXXX`** на открывшейся странице GitHub, затем
  **Continue** и **Authorize**;
- вопрос про Node.js — посоветуй ответить `n`, для правок текста он не нужен.

Попроси её написать тебе, когда скрипт покажет «Всё готово» или красный 🔴.
Если 🔴 — попроси скопировать сюда последние строки из Терминала или
прочитай `~/Desktop/setup-log.txt` сам и объясни, что случилось. Скрипт
можно перезапускать: всё сделанное он пропускает.

### Шаг 4. Проверить результат

Сам выполни и перескажи итог одной строкой на каждый пункт:

```bash
gh auth status
```

```bash
git -C ~/Coding/tatsiana-fitness-coach-landing status -sb
```

```bash
gh api repos/dmitry-rukhlenko/tatsiana-fitness-coach-landing --jq .permissions.push
```

```bash
git config --global user.name; git config --global user.email
```

Что должно быть:

| Проверка | Хорошо | Если нет |
| --- | --- | --- |
| Вход в GitHub | «Logged in to github.com» | Перезапустить скрипт из шага 3 |
| Копия сайта | `## main...origin/main` | Перезапустить скрипт |
| Доступ на запись | `true` | Приглашение не принято: открыть <https://github.com/dmitry-rukhlenko/tatsiana-fitness-coach-landing/invitations> и нажать Accept, или ждать, пока Дмитрий пригласит |
| Подпись коммитов | имя и адрес `...@users.noreply.github.com` | Не исправлять самому, сказать Тане и Дмитрию |

`false` в доступе не мешает продолжить: смотреть и править сайт у себя уже
можно, отправка на GitHub заработает после принятия приглашения.

### Шаг 5. Открыть проект в Claude Code

Объясни, что эта сессия была только для настройки. Работать над сайтом
нужно в новой сессии, открытой в папке проекта, — тогда Claude видит все
файлы сайта.

1. Новая сессия во вкладке **Code**.
2. Выбрать папку `tatsiana-fitness-coach-landing` внутри `Coding` в домашней
   папке. Если не находит — подскажи, что `Cmd + Shift + H` в окне выбора
   открывает домашнюю папку.
3. Первое сообщение в новой сессии:

```text
Прочитай ONBOARDING.md, PRODUCT.md и DESIGN.md и расскажи простыми словами,
что это за сайт, какие тут правила для текста и дизайна и как принято работать.
```

### Шаг 6. Объяснить, как будет устроена работа

Перескажи своими словами, коротко:

- Живой сайт — ветка `main`. Её напрямую не меняют, GitHub это и не даст.
- Каждая задача — новая ветка («черновик»): обновить `main`, создать
  ветку, сделать правки, посмотреть сайт у себя, сохранить и отправить
  pull request. Дмитрий проверит и опубликует.
- Для каждого шага достаточно написать Claude обычными словами; готовые
  фразы есть в `ONBOARDING.md`, раздел «Шаг 6. Как делать правки».
- Пока pull request не опубликован, живой сайт в безопасности, что бы ни
  случилось с её копией.
